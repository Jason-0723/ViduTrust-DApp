# ViduTrust - 基於乙太坊之去中心化醫療志工時數與福利兌換系統

本專案為區塊鏈課程之期末專題成果。旨在利用智慧合約解決傳統醫療志工系統「時數易遺失、數據易篡改、跨院難認證、兌換不透明」之中心化痛點。專案完全於網頁端虛擬區塊鏈環境中完成核心業務邏輯的編譯、布署與模擬驗證。

## 3. 系統功能設計
本合約實作了完整的去中心化積分流通生態圈，主要包含四大核心函數：
1. `mintHours`：**【醫院專用】** 核對服務事實後，增發時數代幣給指定志工。
2. `addProduct`：**【合作商家專用】** 設定福利品名稱與所需積分，上架到區塊鏈列表。
3. `redeemProduct`：**【志工專用】** 消耗個人時數點數，免中介自動兌換商家商品。
4. `settlePoints`：**【醫院/商家】** 商家賺取點數後向醫院申請線下經費核銷，核可後清空鏈上積分。

## 4. 環境準備、編譯與執行說明

本專案採用基於瀏覽器的 **Remix IDE** 開發環境，不需安裝本地節點即可完成執行驗證。

### 步驟一：導入合約原始碼
1. 開啟瀏覽器並進入 [Remix IDE (https://remix.ethereum.org/)](https://remix.ethereum.org/)。
2. 在左側 `File Explorer` 點擊新建檔案圖示，命名為 `ViduTrust.sol`。
3. 將本專案儲存庫中的 `ViduTrust.sol` 程式碼複製並貼入 Remix 編輯器中。

### 步驟二：合約編譯 (Compile)
1. 點擊左側導覽列的 **「Solidity Compiler」**（圖示為一個圓形箭頭）。
2. 將 Compiler 版本選擇為 **`0.8.0`** 以上（或與合約宣告的 `pragma solidity ^0.8.0;` 相符）。
3. 點擊藍色的 **「Compile ViduTrust.sol」** 按鈕。
4. 編譯成功後，左側圖示將出現綠色勾勾。

### 步驟三：部署合約 (Deploy)
1. 點擊左側導覽列的 **「Deploy & Run Transactions」**（圖示為乙太坊標誌）。
2. **ENVIRONMENT（環境）** 選擇 **`Remix VM (Cancun)`**（內建虛擬鏈環境，無需耗時挖礦或消耗真實 Gas）。
3. **ACCOUNT（帳戶）** 預設會提供 10 個內建測試帳戶（皆內含 100 ETH）。預設維持選擇第一個帳戶 `Account(0)` 作為醫院管理方。
4. 點擊橘色的 **「Deploy」** 按鈕。
5. 部署成功後，下方 `Deployed Contracts` 區塊會顯示已部署的合約。

## 5. 系統操作與模擬測試流程

為了驗證系統邏輯，請依序切換 Remix 內建帳戶（Account）進行以下模擬：

### 1. 醫院核發時數給志工
* 保持在 `Account(0)`（醫院地址）。
* 複製第二個帳戶 `Account(1)`（模擬志工）的錢包地址。
* 展開合約面板，找到 `mintHours` 方法。
* 在欄位中輸入志工地址與數量（例如：`Account(1)的地址, 50`），點擊 **transact**。
* 點擊下方 `volunteerBalances` 輸入志工地址查詢，顯示餘額成功變為 `50`。

### 2. 商家上架福利商品
* 切換至第三個帳戶 `Account(2)`（模擬福利合作商家）。
* 找到 `addProduct` 方法。
* 輸入商品參數（例如：`"免費基本健康檢查", 30`），點擊 **transact**。
* 商品成功寫入鏈上，並自動生成商品 ID 為 `1`。

### 3. 志工自主兌換福利
* 切換至第二個帳戶 `Account(1)`（志工地址）。
* 找到 `redeemProduct` 方法。
* 在欄位中輸入剛剛上架的商品 ID：`1`，點擊 **transact**。
* 驗證扣款：呼交 `volunteerBalances` 查詢志工，餘額扣除 30 剩下 `20`；呼叫 `merchantBalances` 查詢商家 `Account(2)`，商家帳戶成功獲得了 `30` 積分。

### 4. 商家經費清算核銷
* 切換回第一個帳戶 `Account(0)`（醫院管理方）。
* 找到 `settlePoints` 方法，輸入商家 `Account(2)` 的地址，點擊 **transact**。
* 查詢 `merchantBalances`，商家的鏈上點數成功歸零，完成線下資金核銷存證。
